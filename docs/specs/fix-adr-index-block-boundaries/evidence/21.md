## Criterion and root cause

A valid ADR index followed immediately by another Markdown block must still pass.
Pipe-containing text outside the table must not be validated as an ADR row. Existing
duplicate, malformed-row, missing-row and field-mismatch checks must remain effective,
including rows without leading pipes and header-absent input.

The scanner resets `in_table` only on blank lines. It therefore collects pipe-containing
text from subsequent headings, block quotes, lists, fenced code and HTML blocks.

## Authorized scope decision

The recommended repair uses Markdown block parsing, retaining raw source rows for ADR
validation so rendering normalization cannot conceal malformed cells. `markdown-it-py`
is already locked as a transitive dependency but needs a direct declaration before use.
The fix skill explicitly requires escalation for a new dependency/config change. The
user overrode that limit: "Let's skip grill for this. Proceed with your new dependency
and fix." The dependency will be declared in the development group because it is used
only by repository tooling. Production and dependency files were unchanged during
both red runs.
