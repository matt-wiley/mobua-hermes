## AC-55 and AC-56: ADR consistency

Script: `scripts/check_adrs.py`, run as `uv run python -m scripts.check_adrs [docs/adr]`. The pure
core is `check(files, index) -> list[str]`. `main` is the filesystem edge: it prints
`<dir>/<file>: <field>: <problem>` to stderr and exits 1, or prints a summary and exits 0.

Tests: `tests/scripts/test_check_adrs.py`, 38 cases. Synthetic inputs, no mocks; a real temp
directory for `main`.

- **Happy path:** a consistent pair passes. Several Amended-by values pass in any order. The real
  `docs/adr` passes: 26 ADRs, including 0024, which amends six ADRs, and 0025, which amends
  0019 and 0024.
- **Failure modes (AC-55):** missing `Status:`/`Date:`, empty `Status:`, a non-ISO date, a repeated
  metadata line, missing or misnumbered title, bad filename, duplicate number, one-way
  `Amends` and one-way `Amended by`, an amendment of an unknown ADR, malformed amendment lists
  (four shapes).
- **Failure modes (AC-56):** ADR missing from the index, listed twice, a row with no file, wrong
  link, title mismatch, status mismatch, Amended-by mismatch (empty, extra, wrong), a row with
  the wrong cell count, a malformed link cell or Amended-by cell, and a missing `README.md`.
- **Boundaries:** no ADRs plus an empty index pass. `Status:` or `Amends:` in the body after the first
  `##` is not read as metadata. Non-Markdown files such as `.DS_Store` are ignored. A missing
  directory exits 1.
- **Edge cases:** all problems are reported together, in a deterministic file order, not just the first.

Red (stubbed `check`/`main` raising `NotImplementedError`):
```
FAILED tests/scripts/test_check_adrs.py::test_the_script_rejects_a_missing_directory
38 failed in 0.05s
```
After the first implementation there was one more failure, a real defect: with no title line,
the first metadata line was skipped as if it were the title. That was fixed by reading
metadata from every line before the first `##`. Green: `38 passed in 0.12s`.

Real broken index (deleted 0025's row and dropped 0025 from 0024's Amended by), using the exact
command CI runs:
```

### Ticket 04 carry-over: isolation level

Decision: pin it. `create_engine_for` passes `isolation_level="READ COMMITTED"` for Postgres URLs.
A server or database default of REPEATABLE READ/SERIALIZABLE otherwise turns a lost promotion
race into `SerializationFailure` (a 503-style database error) instead of
`409 stale_current_selection`. Postgres test databases are set to
`default_transaction_isolation = 'serializable'`, so every Postgres test proves the pin rather
than inheriting Postgres's default.

Test: `tests/service/test_db.py::test_connections_run_at_the_isolation_level_the_promotion_claim_needs`.
Also the four race tests in `test_promotion.py`, including
`test_a_promotion_overlapping_an_uncommitted_sibling_promotion_waits_then_conflicts`.

Red (hostile default, no pin, Postgres):
```
