`NEWS_TEST_DATABASE_URL` names Postgres, `tests/databases.py` migrates one template database per
session and gives each test a `CREATE DATABASE … TEMPLATE` copy, dropped afterwards with `WITH (FORCE)`
in a `finally`. A URL for any other backend raises a `pytest.UsageError`.

Tests:
- `tests/test_test_database.py::test_the_engine_fixture_uses_the_configured_database`
  (happy path, both backends).
- The whole existing `tests/service` suite, including `test_schema.py` (AC-53 schema/scope tests,
  autogenerate-diff against models, downgrade to empty).

Changes needed for Postgres, all in tests:

  deferred FK. The promotion test now expects `IntegrityError` matching `(?i)foreign key`
  rather than any `Exception` with SQLite's casing.
- The WAL and `foreign_keys` PRAGMA tests use an explicit `sqlite_engine`. They test SQLite's
  own connection settings, so they run on SQLite in both runs.

### Ticket 04 carry-over: isolation level

Decision: pin it. `create_engine_for` passes `isolation_level="READ COMMITTED"` for Postgres URLs.
A server or database default of REPEATABLE READ/SERIALIZABLE otherwise turns a lost promotion
race into `SerializationFailure` (a 503-style database error) instead of
`409 stale_current_selection`. Postgres test databases are set to
`default_transaction_isolation = 'serializable'`, so every Postgres test proves the pin rather
than inheriting Postgres's default.

Test: `tests/service/test_db.py::test_connections_run_at_the_isolation_level_the_promotion_claim_needs`.
Also the four race tests in `test_promotion.py`, including
`test_a_promotion_overlapping_an_uncommitted_sibling_promotion_waits_then_conflicts`.

Red (hostile default, no pin, Postgres):
```
E   AssertionError: assert 'SERIALIZABLE' == 'READ COMMITTED'
E   sqlalchemy.exc.OperationalError: (psycopg.errors.SerializationFailure) could not serialize access due to concurrent update
FAILED tests/service/test_db.py::test_connections_run_at_the_isolation_level_the_promotion_claim_needs
FAILED tests/service/test_promotion.py::test_a_pointer_change_racing_the_promotion_is_a_conflict_after_rollback
FAILED tests/service/test_promotion.py::test_a_save_racing_the_promotion_is_a_conflict_after_rollback
FAILED tests/service/test_promotion.py::test_a_sibling_promotion_racing_for_the_same_number_is_a_conflict_after_rollback
FAILED tests/service/test_promotion.py::test_a_promotion_overlapping_an_uncommitted_sibling_promotion_waits_then_conflicts
5 failed, 15 passed in 3.60s
```
Green with the pin: `20 passed` on both backends. The overlapping sibling promotion waits on the
Plugin-row claim (`waited >= 0.3s`), then gets `stale_current_selection`, with no deadlock and no
database error. Before the hostile default, these tests already passed on Postgres at its own
default.
