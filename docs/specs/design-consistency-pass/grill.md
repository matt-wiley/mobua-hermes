# Grill: Design consistency pass

The confirmed [Plugin drafts amendment](../plugin-drafts/grill.md) is incorporated into
this same [spec](spec.md) by user instruction on 2026-10-17. Pending ticket numbers and
responsibilities were revised; see the [implementation plan and historical map](tickets/README.md).
The original decisions below remain the historical source for the base scope, qualified
by the amendment and ADRs 0024/0025. Completed ticket evidence is unchanged.

Resolve the contradictions, ambiguities, and gaps found in the review of `CONTEXT.md` and `docs/adr/` (2026-10-16), before any spec is written.

## Branches
| # | Branch | Status | Decision |
|---|---|---|---|
| 1 | Scope of this pass: which findings get decided here vs. explicitly deferred | resolved | Decide 2–18 here. For each of 19–27, either decide here or defer explicitly to a named later grill; the deferral is itself recorded as the decision. |
| 2 | Plugin definition vs. per-Channel instance (where Plugin config lives; ADR 0016) | resolved | Plugin = Reader-owned identity with immutable Plugin Revisions (Manifest, code, config schema, creator). Channel keeps identity + Channel Revisions. A Channel Revision holds Plugin Bindings, each pinned to one exact Plugin Revision with that Channel's config. Upgrades are explicit per Channel and re-validate config. Owner on Plugin (scoping); creator on Plugin Revision (provenance only, no domain term yet). [ADR 0018](../../adr/0018-plugin-bindings-pin-plugin-revisions.md), amends 0016. |
| 2a | Can a Channel Revision have zero Plugin Bindings (e.g. while being set up)? | resolved | Yes. The scheduler skips Collections for a Channel whose current Revision has no Bindings, and Channel Health flags "no Plugins attached". Publishing still runs (normally publishes nothing). Feeds into branch 10. |
| 3 | Built-in Plugins vs. Reader scoping (ADR 0007) | resolved | One system-owned, read-only Built-in Plugin per built-in, no Reader id, shared Revision history seeded from app code when it changes. Bindings may reference Reader-owned or Built-in Plugin Revisions (single service-layer rule). Readers Eject a copy to diverge: new Reader-owned Plugin, no lineage. [ADR 0019](../../adr/0019-built-in-plugins-are-shared-and-ejectable.md), amends 0007 and 0018. |
| 4 | Plugin isolation: what a Plugin Run can reach (env, data volume, network); ADR 0008's "never see real keys" guarantee | resolved | v1 hardening: clean env (basics + declared Secrets + Gateway URL/token), separate unprivileged OS user with no access to data volume/Master Key/Core files, per-run temp dir, CPU/memory/file-size limits. Network allowed. Stated trust model: not a sandbox against malicious code; run only trusted Plugins. Namespace sandbox deferred until public Plugin sharing. ADR 0008 guarantee reworded; SECURITY.md scope updated. [ADR 0020](../../adr/0020-plugin-runs-hardened-not-sandboxed.md) |
| 5 | Model scoping: one Model per Channel vs. an allowlist (glossary, ADRs 0008, 0012) | resolved | Reader owns LLM Providers and enabled Models; a Channel Revision configures a set of named Channel Models from them, one marked for writing; Plugins hold no LLM config and request turns through the Channel by name (Gateway call, token scoped to the Channel's Channel Models). [ADR 0021](../../adr/0021-channel-models.md), amends 0008 and 0012. |
| 5a | How Plugins refer to a Channel's Models | resolved | By Channel Model name only. Names are required and free-form (UI suggests e.g. `writer`, `vetter`); exactly one Channel Model is marked for writing Articles. Term **Channel Model** added. |
| 5b | Which Plugin Bindings may call which Channel Models; behavior on unknown/denied name | resolved | Every Plugin bound to a Channel may call any of that Channel's Channel Models; no per-Binding access control. A call naming a Channel Model the Channel doesn't define is refused by the Gateway with a clear error and logged to Channel Health. Runaway-cost protection therefore rests on branch 26. |
| 5c | Vetting and history checks as Channel-side steps on the Feed (new pipeline stages beyond Publish's group-and-write) | resolved | No new processes; Collection and Publish remain the only two. Checking past Articles is a step of Publish (preparing context before writing; Publish glossary entry updated). Vetting is a Channel step, not a Plugin's job; whether it belongs to Collection or Publish is **deferred to the Channel contracts grill** (Plugin→Channel and Channel→Core edges). Recorded in ADR 0021. |
| 6 | Channel storage wording: ADR 0006 "own storage" vs. ADR 0013 shared DB | resolved | Wording fix only: ADR 0006 now says each Channel's data is logically separate, as rows in the shared database scoped by Channel and Reader (ADR 0013). |
| 7 | Scheduler ownership: ADR 0002 (Channels run schedules) vs. ADR 0014 (scheduler in Core) | resolved | Wording fix: Channels own their cadences (on the Channel Revision) and next-run-at state; a shared scheduler in the service layer only carries them out and never sets a rhythm. ADR 0014 "in the Core" → "in the service layer"; ADR 0002 gains a consequence line. Extended: Core = central app experience (design concept), service layer = central shared code. Glossary Core/Service layer reworded; code-sense "Core" reworded to "server process"/"app"/"backend" in ADRs 0006, 0008, 0011, 0020; new avoid entry. |
| 8 | Inbox vs. past Articles; what Aggregation does in a shared DB (ADR 0003 "two places") | resolved | **Deferred to the Channel contracts grill**, as part of designing the Channel→Core contract. Not patched here, since a wording fix now would likely be redone. |
| 9 | ADR 0006 Core–Channel interface list completeness | resolved | ADR 0006 now lists all seven seams: Aggregation, Style reads, LLM Gateway calls, Secret delivery, scheduler run triggers, Channel Health reports, Channel configuration. Aggregation's shape deferred to the Channel contracts grill. |
| 10 | Channel Health definition vs. its uses (ADRs 0010, 0015) | resolved | Widened to problems needing the Reader's attention: failed Plugin Runs, rejected News Items, refused Channel Model calls, missing Plugin Bindings. Each Plugin Run keeps its own size-capped stderr log; Channel Health links to logs of flagged runs rather than collecting all output. Glossary Channel Health + Plugin Run reworded; ADR 0015 stderr sentence reworded. |
| 11 | Partial output from a failed Plugin Run (glossary vs. ADR 0005) | resolved | All or nothing: a Plugin Run's output is buffered and ingested only on exit code 0; a failed or killed run contributes nothing. Dedup by News Item id means the next Collection recovers the items. ADR 0005 reworded; glossary already matched. Settled input for the Channel contracts grill. |
| 12 | Citation failure: reject vs. regenerate; fate of the Topic's News Items (ADR 0010) | resolved | Regenerate with the failed Citations fed back to the writing Channel Model, up to a per-Channel-Revision retry limit (default 2); then reject: no Article, failure + unmatched Citations to Channel Health, Topic's News Items stay unused for later Publishes until the Retention Window drops them. ADR 0010 reworded. |
| 13 | Catch-up ordering: Collection then Publish (glossary vs. ADR 0014) | resolved | When both cadences are due, Collection runs first and Publish starts after it finishes. A run blocked by the Run Lease stays due (next-run-at not advanced) and starts on the first poll after release; never dropped. ADR 0014 reworded; glossary Catch-up and Run Lease reworded. |
| 14 | ADR Status/Date fields (CONTRIBUTING says "accepted"; ADRs have none) | resolved | All 21 ADRs carry `Status: Accepted`, `Date: 2026-10-16`, and two-way `Amends:` / `Amended by:` links (0015←0016, 0016←0018, 0007←0019, 0018←0019, 0008←0020, 0008←0021, 0012←0021). In-text amendment notes kept. CONTRIBUTING describes the block. |
| 15 | ADR 0007 list of Reader-scoped records | resolved | Enumerated list replaced by a rule: every record carries a Reader id except Built-in Plugins and their Revisions (ADR 0019) and app-wide records with no Reader data; records belonging to a Channel also carry its Channel id; examples given. ADR 0013 reworded to "scoped by Reader, and by Channel where the row belongs to one". |
| 16 | Glossary gaps: Built-in Plugin, data key, Gateway token | resolved | Built-in Plugin added in branch 3. Added **Data Key** (Reader's key for Secrets, wrapped by the Master Key) and **Gateway Token** (short-lived, scoped to the Channel's Channel Models, never a real provider key). Avoid: "API key" for Plugin LLM access. Data Key's coverage of LLM Provider credentials left to branch 20. |
| 17 | ADR index (`docs/adr/README.md`) | resolved | Added `docs/adr/README.md` (number, title, status, amended by); hand-maintained, CONTRIBUTING says to update it with each ADR; linked from README. Automated consistency checking was subsequently canceled by the user on 2026-10-18; the index remains hand-maintained. |
| 18 | Roadmap / phases (ADR 0017 mentions "Phase 1") | resolved | ADR 0017 reworded to drop the undefined "Phase 1" (now "before the Web App exists"). Roadmap itself **deferred to a roadmap grill**. |
| 19 | Authentication for Web App, API, Syndication Feed | resolved | **Deferred to an auth grill**, before the Web App or Syndication Feed is specified. Must cover: single-Reader localhost vs. server deployment; sessions vs. tokens; Syndication Feed URL tokens (feed readers can't log in); the CLI's in-process trust (ADR 0017); scheduled runs while the Reader is logged out (ADR 0009). |
| 20 | LLM Provider credential storage | resolved | Encrypted with the Reader's Data Key (same envelope scheme as Secrets, ADR 0009). Decrypted only inside the LLM Gateway, in memory, at call time; never passed to Plugin Runs or logged. Kept distinct from Secrets. Recorded as an in-place note in ADR 0009; Data Key glossary entry widened. |
| 21 | Core agent: which Model, which cadence | resolved | Principles settled: the Core agent uses one of the Reader's enabled Models, chosen as a Reader setting; it runs on the same service-layer scheduler as Channel cadences (ADR 0014 scope note; same lease and Catch-up). **Deferred to a Style grill**: what triggers a draft (cadence, Feedback count, on demand), how much Feedback it reads, how Style Proposals are presented and applied. Core agent glossary entry updated. |
| 22 | Plugin runtimes and dependency installation in the container | resolved | v1 image ships Python and a POSIX shell; Plugins use runtimes present in the image. Python Plugins declare dependencies inline (PEP 723), pinned exactly (`==`, unpinned rejected at validation), run with `uv run`; cache owned by the Plugin OS user. [ADR 0022](../../adr/0022-plugin-runtimes-and-pinned-inline-dependencies.md), amends 0005 and 0011. |
| 23 | Prompt injection from retrieved content | resolved | Three v1 principles: retrieved content is untrusted data, kept in delimited blocks separate from instructions; no tool use in the Gateway, and adding it requires revisiting injection first (ADR 0012 consequence); Article output rendered through an allowlist sanitizer, never raw LLM HTML. Rules added to `docs/standards.md` overrides; SECURITY.md scope updated. Not ADR-worthy (coding rules). **Content-level defenses** (e.g. vetting for manipulated sources) **deferred to the Channel contracts grill**. |
| 24 | Cadence format and time zones | resolved | Each cadence on a Channel Revision is either an interval (e.g. every 2h) or a cron expression. Cron cadences use the Reader's time zone, a Reader setting defaulting to UTC; no per-Channel zones in v1. next-run-at stored in UTC; DST via `zoneinfo`. Not ADR-worthy. |
| 25 | Retention Window default | resolved | Set per Channel on the Channel Revision; default 14 days. A Channel Revision whose Retention Window is not longer than its Publishing interval (for cron: the longest gap between scheduled runs) is rejected at save. Not ADR-worthy. |
| 26 | LLM spend limits | resolved | Daily token budgets enforced in the Gateway: per Channel (default 500k tokens/day, covers Publish and Plugin turns) and per Reader across all Channels and the Core agent (default 2M/day). Either may be set to unlimited explicitly. Must be easy for the Reader to change. Tokens, not dollars. Exhausted budget: Gateway refuses calls until the day resets in the Reader's time zone, refusal to Channel Health, unfinished Topics stay unused. Branches 26–26e recorded together in [ADR 0023](../../adr/0023-llm-usage-budgeted-recorded-attributed.md), amends 0012. |
| 26a | Budgets linked to LLM Providers: knowing which Provider is budget-starved | resolved | Optional per-LLM-Provider daily cap (Reader setting, unlimited by default). Three nested budgets — Channel, Provider, Reader — and a call proceeds only if all have room. Every refusal recorded in Channel Health names which budget ran out and the Provider and Model of the call. |
| 26b | Model Health: checking that LLM Providers and Models are reachable | resolved | New Reader-level **Model Health** per LLM Provider and Model (auth valid, Model available, recent errors/rate limits). Fed by (1) every Gateway call failure, (2) an hourly check on the shared scheduler using the Provider's model-listing endpoint where available (no tokens), (3) a tiny real call on Provider save and an on-demand "test" action. Channels whose Channel Model points at an unhealthy Model get a Channel Health entry linking to it. |
| 26c | Gateway metrics for Model usage and efficiency | resolved | Two layers. (1) Durable per-call record in the database: time, Reader, Channel, caller (Publish step / Plugin Binding / Core agent), Channel Model name, Provider, actual Model id, tokens in/out, latency, outcome (ok / error kind / refusing budget), citation-retry flag; kept 90 days by default (adjustable). Feeds budgets, Model Health, breadcrumbs, efficiency analysis. (2) Prometheus `/metrics`: `gateway_calls_total{provider,model,outcome}`, `gateway_tokens_total{provider,model,direction}`, `gateway_call_duration_seconds{provider,model}`, `gateway_budget_refusals_total{budget,provider}`; no Reader/Channel labels. Model-comparison UI left to the roadmap grill. |
| 26d | LLM breadcrumbs: every LLM-produced output records the Model(s) involved | resolved | Every LLM-produced output carries a permanent **Model Attribution**: list of {step, Channel Model name, Provider, Model id}, copied onto the output (like Citations, ADR 0010) and linked to the call records while they exist. Articles: every LLM step incl. each citation retry. Style Proposals: the Core agent's Model. News Items: via their Plugin Run, which carries the Attribution for the turns it made. |
| 26e | Where budgets live (Channel Revision vs. operational setting) so they're easy to change | resolved | The Channel daily budget is an operational setting on the Channel identity, not the Channel Revision (it doesn't shape content). Changes apply immediately to the current day; already-spent tokens stand. Reader cap, Provider caps, and call-record retention are ordinary Reader/Provider settings. Content-shaping config (Channel Models, Plugin Bindings, cadences, Retention Window, citation retry limit) stays on the Channel Revision. |
| 27 | Topic grouping method | resolved | LLM grouping returning schema-validated JSON (Topics → News Item ids), given unused items' titles, summaries, ids, and recent past-Article context. Channel enforces: each Topic lists ≥1 item; unknown or non-unused ids discarded; ungrouped items stay unused; grouping appears in Model Attribution. **Per-step Channel Models**: grouping, past-Article check, and writing each name a Channel Model; writing is required, the others inherit it unless set ("default to simple, allow complex"); citation retries use the writing Model. Judgment steps are defined as typed decisions (state + typed questions → typed answers), answered by generative Models via schema JSON. Embedding-based clustering deferred until the Gateway adds embeddings. **Deferred to a spike**: usability of discriminative decision models (Jev cited as an example only, not a target) — needs a Gateway `decide`-style call and adapter. ADR 0021 updated in place; Channel Model glossary entry reworded. |

## Terms added to CONTEXT.md
- **Plugin Binding** (new); **Plugin**, **Revision**, **Channel** reworded. Avoid: "Plugin instance"/"Plugin config", "version".
- **Built-in Plugin**, **Eject** (new); **Plugin** reworded for system ownership. Avoid: "Fork".
- **Channel Model** (new); **Model** reworded.
- **Core**, **Service layer** reworded (design concept vs. code); **Publish**, **LLM Gateway** reworded. Avoid: "Core" for the server process or container.
- **Channel Health**, **Plugin Run**, **Catch-up**, **Run Lease** reworded.
- **Model Health**, **Model Attribution** (new).
- **Data Key**, **Gateway Token** (new); **LLM Gateway**, **Master Key** reworded. Avoid: "API key" for Plugin LLM access.
