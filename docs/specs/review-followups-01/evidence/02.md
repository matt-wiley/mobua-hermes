# Evidence: review-followups-01-02

The CLI's root Typer now uses `_TopLevelGroup`, a `TyperGroup` whose `invoke` is the one place that handles failures:
- Typer's own `Exit`, `Abort` and usage errors pass through unchanged, so `--config` parse errors still exit 2.
- Expected failures are `ValidationRejected`, `ChannelNotFound` and `ReaderNotFound`. stderr gets the lines from `expected_failure_lines`, then the command exits 1. The service layer has already logged them.
- Any other `Exception` is logged as `cli.unexpected_error` at `error` level, with `command` and `exc_info`. stderr gets one line from `unexpected_error_line`, and the command exits 1.

The message text comes from a pure module, `news.cli.messages`. The root callback stores the log path in `ctx.meta`. The sub-Typers use `_CommandGroup`, which records the resolved subcommand names in `ctx.meta` so the log can name `channel bind`. The per-command `try`/`except` blocks and `_fail` are gone. Each command now captures its result inside `_transaction` and echoes it after the block, which is after the commit.

`ctx` is typed `Any` in the two overrides, with a comment. Typer 0.27 vendors Click, and the `Context` these methods receive (`typer._click.core.Context`) has no public name. Annotating it `typer.Context` would be wrong at runtime and fails pyright's override check.

Every red run used a stub that imports cleanly, or code that already existed, so each failure shows missing behavior and not an import error.

## AC-18: a failed commit prints nothing, exits 1 through AC-13, and saves nothing

**Tests**
- `test_a_command_whose_commit_fails_prints_nothing_and_saves_nothing[reader|plugin|channel|bind]`: the real commit-failure seam.
  - A second `sqlite3` connection adds a trigger on the table the command inserts into (`reader`, `plugin_revision`, `channel`, `channel_revision`). The trigger writes a dangling `DEFERRABLE INITIALLY DEFERRED` foreign key.
  - SQLite checks deferred keys only at COMMIT, so the command's flush succeeds and its commit fails with `IntegrityError: FOREIGN KEY constraint failed`.
  - Asserts exit 1 as `SystemExit`, stdout `== ""`, stderr exactly one AC-13 line, a `cli.unexpected_error` whose traceback passes through `commit`, and an unchanged row count.
- `test_a_command_that_fails_at_flush_prints_nothing_and_saves_nothing`: holds the write lock, runs `reader create`, releases the lock, and then counts 0 Readers.
- `test_output_is_printed_only_after_the_transaction_has_committed[reader|plugin|channel|bind]`: a spy on `typer.echo` checks from a second connection that the write lock is free at each print (D-9).

**Categories**
- Failure modes: commit failure for all four writing commands, and flush failure from lock contention. Both use real SQLite, with no mocks of the database.
- Happy path (D-9): all four writing commands print only after commit.
- Output boundary: stdout is exactly empty on failure.
- Edge cases: n/a beyond the above. `db upgrade` already echoed after `migrate()` committed.

**`cli.unexpected_error`'s `command`** names only the commands resolved so far. A failure in the root callback logs the group, for example `reader`, because the subcommand has not been resolved yet.
