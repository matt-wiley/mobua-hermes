## Notes for review
- **`(root)` in exception messages:** `ValidationRejected` now shows an empty field as `(root)`, matching the CLI's existing display and the ticket's "empty `field` shown at the root". Before, `ManifestError` and `ChannelRevisionRejected` rendered it as `": <message>"`. Only `str(exception)` changed. `errors`, the log payloads and the CLI output did not.
- **Duplicate `(root)` formatting:** the CLI's `_fail` still formats `(root)` itself. Left for ticket 02, which consolidates CLI error handling.
- **Check order:** `create_plugin` checks the Reader before parsing the Manifest. An unknown Reader with a bad Manifest reports `no Reader`.
