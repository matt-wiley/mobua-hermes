# Evidence: review-followups-01-05

What changed:
- Each model declares its scope through `__table_args__ = scoped("reader" | "channel")` in `news.service.models`. `scoped()` returns a fresh dict on every call, because SQLAlchemy keeps the dict it is given as `Table.info`. A shared module constant made `reader.info is plugin.info` true, so a write to one table's `info` would have leaked into the others.
- `READER_SCOPE_EXEMPT_TABLES` is removed, and the module docstring now states the scope rules.
- `tests/schema_rules.py` holds two pieces:
  - the pure rules: `TableDescription` and `scope_violations()`;
  - the edge: `describe_tables(engine, metadata)`, which combines `inspect(engine)` with `Table.info`. `alembic_version` counts as `app` through `UNMODELLED_TABLE_SCOPES`.

Declared scopes: `reader`, `plugin` and `plugin_revision` are `reader`; `channel`, `channel_revision` and `plugin_binding` are `channel`.

**Categories**

- Failure modes: one test for each AC-2 rule, plus a `channel` table with no `reader_id` (see the note below).
- Boundaries:

  - a malformed scope (`"global"`);
  - several violations in one schema, all reported in table order.
- Edge cases:
  - a foreign key from an `app` table, not only from a `reader` table;
  - a foreign key to `channel_revision`, a `channel` table other than `channel` itself.

**Note: a `channel` table must also carry `reader_id`.** AC-2's list doesn't name this rule. The old test (`test_every_table_has_a_reader_id_except_declared_exemptions`) did require `reader_id` on every Channel table, and ADR 0007 says every record carries a Reader id. Without this rule, replacing the old test would have weakened it. The review accepted this, and AC-2 in the spec is now amended to list it, along with the "unknown scope" rule (D-3).
