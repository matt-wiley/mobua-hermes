# Evidence: review-followups-01-01

`news` now takes `--log-file` (env `NEWS_CLI_LOG_FILE`). The root callback resolves the path (pure `news.cli.log_file.resolve_log_path`), creates the directory, opens the file in append mode before the engine is created, and passes it to `configure_logging(stream=...)`. The context closes the file. When the file can't be opened, the CLI prints one stderr line and exits 1. The server default (`configure_logging()` with no stream) is unchanged.

Every red run used a stub that imports cleanly, so the failures show missing behavior and not import errors. The stubs were a `resolve_log_path` that raises `NotImplementedError`, a `stream` parameter that is accepted but ignored, and a `--log-file` option that is accepted but ignored.

Test support: `tests/cli/conftest.py` has an autouse fixture that points `NEWS_CLI_LOG_FILE` into `tmp_path`, so no test writes to the real state directory (checked: `~/.local/state/news/` does not exist after the run). It also resets structlog afterwards, so no later test logs to a closed file.

**Categories**

- Edge cases: a missing directory is created. Every CLI case starts with no `logs/`, `state/news/` or `home/.local/state/news/` directory.
- Failure modes: covered under AC-11.

## AC-11: an unopenable log file exits 1 before the database is touched

**Tests**
- `tests/cli/test_cli.py::test_an_unopenable_log_file_fails_before_touching_the_database`: the path is under a `0o500` directory in `tmp_path`. The test asserts exit 1, empty stdout, and a stderr that holds the path, `Permission denied`, `--log-file` and `NEWS_CLI_LOG_FILE`. The SQLite file does not exist afterwards.
- `tests/cli/test_cli.py::test_a_log_file_path_that_is_a_directory_is_reported`: exit 1, the path is on stderr, and no database is created.

**Categories**
- Failure modes: a permission error on `mkdir`, and a directory where the file should be (`IsADirectoryError` on open).
- Happy path: covered by AC-9 and AC-10.
- Boundaries and edge cases: the directory case above.

**Design note:** I first gave the option `dir_okay=False`. Typer then rejected a directory with a usage error (exit 2), boxed and word-wrapped so the path wasn't intact on stderr. That check doesn't run for the env var at all, so I removed it. Both cases now go through the same handler and exit 1.

**Red:**
